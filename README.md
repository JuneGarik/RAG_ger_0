# БЗПО — база знаний проектного опыта

RAG-система на русскоязычном корпусе проектных документов (КП, отчёты, акты,
презентации), разворачивается on-premise. Назначение — собирать из накопленного
опыта черновики разделов тендерных заявок и описаний подхода со ссылками на
источники и подтверждающие документы.

Рабочие документы: [`docs/about/SPEC.md`](docs/about/SPEC.md) — техническая спецификация
v1.1, [`docs/about/PLAN.md`](docs/about/PLAN.md) — план разработки,
[`docs/about/recs.md`](docs/about/recs.md) — замечания ревью, на которых стоит SPEC v1.1.

## Быстрый старт: веб-интерфейс

```bash
cd ~/project/RAG_v1 && ./start.sh      # откроется http://localhost:8501, остановить — Ctrl+C
```

Скрипт сам запускает Postgres.app и Ollama, если они не запущены. Вкладки:
«Подход» (генерация), «Поиск», «Документы» (добавить файл, черновик строки
реестра, открыть реестр, проиндексировать), «Черновики». В боковой панели —
состояние системы, режим быстро/тщательно, фильтр по типу материала (отчёт,
КП…) и по конкретным документам. Первая установка — `docs/LAPTOP.md`;
интерфейсу нужен extra `ui`: `pip install -e ".[dev,db,local,registry,ui]"`.

## Профиль ноутбука

`config.yaml` настроен на запуск целиком на MacBook (Apple Silicon, 16 ГБ):
эмбеддер Giga-Embeddings-instruct-480M и реранкер bge-reranker-v2-m3 в
процессе на MPS; в Ollama Qwen3.5 9B отвечает на запросы, GigaChat 3.1
Lightning пишет шапки чанков при индексации. Установка и выбор
моделей — [`docs/LAPTOP.md`](docs/LAPTOP.md). Внешний сервис включается
обратно строкой `external.provider: external`.

## Состояние

Закрыт этап 0.5: конфигурация, миграция 0001, модуль изоляции внешнего сервиса,
чистые алгоритмы поиска (RRF, MMR, boost) и тесты к ним.

Работает сквозной путь для презентаций в md: реестр Excel → проекты →
индексация (слайд = чанк, два вектора) → поиск (вектор + FTS → RRF →
реранкер → boost → MMR, фильтр публичности):

```bash
export BZPO_DB__DSN=postgresql://localhost/bzpo
python -m bzpo.ingest                       # реестр + индексация, повтор идемпотентен
python -m bzpo.search "сколько провели интервью" -k 5 [--full]
python -m bzpo.generation approach "цель нового проекта" --area "отрасль" --situation "ситуация"
```

Генерация описания подхода (сценарий Б): поиск по 6 граням подхода → контекст с
подписями источников → Qwen с `generation/prompts/approach_system.txt` →
проверка без LLM (числа, ссылки, перенос ситуации нового заказчика в факты
прошлых проектов, утверждения без источника и без `[вывод]`) → «Источники» по
процитированным номерам. Черновик сохраняется в `data/drafts/`. Около 3 минут
на ноутбуке: ~30 с поиск, ~2,5 мин генерация.

Конвертация pptx → md без модели (этап П1 `docs/PARSING_PLAN.md`) и проверка
md против XML pptx:

```bash
python -m bzpo.parsing convert data/samples/отчёт.pptx      # -> data/converted/отчёт.md
python -m bzpo.parsing check data/samples/отчёт.pptx data/samples/отчёт.md
```

Ещё не написаны: разбор запроса и HyDE (этап 3.5), генерация раздела (этап 4:
сборка контекста, промпт, проверка чисел уже есть в generation/), датасет и
прогон оценки (этап 3), UI, разбор docx/pdf, секционный индекс, дедупликация.

## Структура

```
bzpo/
  config.py      конфигурация: config.yaml + окружение, валидация, config_hash
  ingest/        чанкинг, обогащение, дедупликация, индексация      (этап 2)
  registry/      загрузчик реестра из Excel, валидации              (этап 2)
  storage/       репозитории PostgreSQL; весь SQL живёт только здесь
  providers/     модуль изоляции: Embedder/Reranker, клиент Ollama
  parsing/       разбор запроса: классификация, параметры, HyDE     (этап 3.5)
  search/        RRF, boost, MMR; запросы к БД — в storage/
  generation/    сборка контекста, маркеры, два списка              (этап 4)
  eval/          резолвер якорей, прогон датасета, гейт регрессии   (этап 3)
  ui/            Streamlit                                          (этап 4)
  migrations/    нумерованные SQL-миграции
config.yaml      образец конфигурации стенда
tests/           pytest; ни базы, ни сети
```

Границы модулей: обращения к базе — только из `storage/`, к сети — только из
`providers/`. Правило проверяется тестом `tests/test_boundaries.py`, который
разбирает AST исходников и падает на подложенном нарушении.

## Как запустить тесты

```bash
python -m pytest tests/ -q     # ни PostgreSQL, ни внешний сервис не нужны
python -m ruff check .
```

`conftest.py` добавляет корень проекта в `sys.path`, поэтому установка пакета
для прогона тестов не требуется. Полная установка окружения разработки:

```bash
pip install -e ".[dev]"        # + ".[db]" для psycopg, когда понадобится база
```

## Конфигурация и секреты

Параметры — в `config.yaml`, любой переопределяется окружением:
`BZPO_SEARCH__TOP_K_FINAL=5`. Секреты в файл класть нельзя, загрузчик падает с
ошибкой; они задаются только окружением:

```
BZPO_EXTERNAL__TOKEN=...        токен сервиса эмбеддингов и реранкинга
BZPO_DB__DSN=postgresql://...   подключение к PostgreSQL
```

`Settings.config_hash` — sha256 конфигурации без секретов, пишется в каждую
трассу (SPEC раздел 8); ротация токена хэш не меняет.

## Реестр проектов и новый проект

Реестр — `data/registry.xlsx` (вне git): лист «Проекты» с колонками прежней
таблицы плюс «Результат тендера» и «Статус записи», лист «Документы» (файл →
проект), лист «Легенда». Новый документ вносится черновиком:

```bash
python -m bzpo.registry draft data/samples/<отчёт>.md   # реестр закрыт в Excel
```

GigaChat Lightning заполняет поля по «паспортным» слайдам; роли и практики
команды берутся правилом из таблицы «ФИО | Должность»; каждое значение
сверяется со слайдами (фамилии, даты, числа). Жёлтое — проверить, оранжевое —
не подтвердилось. Публичность ставит человек; результат тендера — правилом:
есть отчёт или акт — `won`, только КП — выбирает человек. Загрузчик берёт
строки со статусом «проверено».

## Миграции

Решение этапа 0.5 зафиксировано: собственный раннер поверх нумерованных
SQL-файлов, **не Alembic** (обоснование — в докстринге
`bzpo/storage/migrate.py`). Применение:

```bash
python -m bzpo.storage.migrate --dsn postgresql://...
```

Раннер идемпотентен, транзакция — на миграцию, правка уже применённой миграции
отвергается. Ручные правки схемы на стенде запрещены.

## Расхождение со SPEC, требующее решения

`CONTEXT_BUDGET_TOKENS` в конфигурации равен **11000**, а не 12000 из SPEC
раздела 10. Причина арифметическая: SPEC требует проверять бюджет контекста
токенизатором GigaChat с запасом 20% и держать окно Ollama `num_ctx = 16384`,
но 12000 × 1.2 + 3000 = 17400 > 16384. Тройка (12000, ×1.2, 3000)
несовместима; валидация конфигурации такую комбинацию отвергает
(`tests/test_config.py::test_context_budget_overflow_fails`). 11000 — максимум,
проходящий проверку. Альтернатива — поднять `num_ctx` до 17408, но это
упирается в KV-кэш карты и требует замера из пробы GigaChat (этап 0.3).
Решение принимается по факту замера; до тех пор действует 11000.

## Что заблокировано внешними ответами (этап 0)

Написанный код осознанно параметризован по этим неизвестным — их значения
меняют конфигурацию, а не код:

| Неизвестное | Где ждёт значения | Чем блокирует |
|---|---|---|
| Диалект реранкера (TEI или Cohere/Jina) | `external.rerank_dialect` | реализованы оба, автоопределения нет |
| Сколько пар реранкер принимает за вызов | `external.rerank_batch` | расчёт латентности: 6 или 300 обращений на запрос |
| Предел длины входа сервиса | `external.max_input_chars`, `chunking.chunk_hard_limit_embed` | усечение входа эмбеддера |
| Схема лимита 20 rps (запросы или элементы) | `external.rate_limit_rps` | спейсинг запросов |
| Ревизии развёрнутых моделей | `external.embed_model_revision` | ключ кэша векторов запросов |
| Health-эндпоинт | `external.health_path` | синтетическая проба доступности |
| Скорость GigaChat и реальный `num_ctx` | `ollama.*`, `generation.context_budget_tokens` | бюджет латентности и расхождение выше |
| `RERANK_THRESHOLD` | `search.rerank_threshold` (null) | отсечение «не найдено» до калибровки не применяется |

Первые шесть снимаются прогоном `docs/about/probe_api.py` (задача 0.2), седьмой —
пробой GigaChat (0.3), последний калибруется на этапе 3.6 на ≥15 запросах
без ответа.
