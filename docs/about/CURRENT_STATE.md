## 1. Что это и для кого

База знаний проектного опыта консалтинговой компании. Пользователи — 12
руководителей проектов и 6 директоров (перспектива — до 100). Система:

1. **принимает документы прошлых проектов** — отчёты и КП в pptx, отчёты в Word
   (в том числе со скриншотами слайдов) — и превращает их в md;
2. **ведёт реестр проектов** (Excel): заказчик, публичность, результат тендера;
3. **ищет по смыслу** по всем слайдам и разделам с фильтром публичности;
4. **пишет черновик подхода к новому проекту** по шести граням со ссылками на
   слайды-источники, проверкой каждого утверждения и достоверностью по граням.

Всё работает локально: документы заказчиков не уходят во внешние сервисы.

## 2. Что работает сейчас

- Загрузка pptx, docx, md через веб-страницу; формат определяется по содержимому.
- Конвертация в md: тексты, таблицы, данные и подписи диаграмм, тепловые карты,
  шкалы-оценки — кодом из XML; картинки и скриншоты — мультимодальной моделью.
- Проверка md против исходного pptx: полнота текста и числа без опоры.
- Реестр: черновик строки от GigaChat, проверка и решения человека на странице.
- Индексация с версиями индекса, выбор документов для индексации.
- Поиск: вектор + полнотекст → RRF → реранкер → boost → MMR.
- Генерация подхода (сценарий Б SPEC) с проверкой и достоверностью по граням.
- Веб-интерфейс Streamlit с блокировкой одновременных тяжёлых операций.
- 203 автотеста без базы и сети; ruff.

## 3. Путь документа: от файла до поиска

```
файл (pptx/docx/md)
  │ 1. detect — формат по содержимому (zip Office / md со слайдами / md-документ)
  ▼
  │ 2. convert — md по контракту: код извлекает из XML, модель разбирает картинки,
  │    проверка против исходника (pptx)                      data/samples/*.md
  ▼
  │ 3. registry draft — GigaChat заполняет строку реестра, код проверяет поля
  │    по слайдам; человек ставит код, публичность, тендер, «проверено»
  ▼                                                          data/registry.xlsx
  │ 4. ingest — проверенные строки -> проекты в БД; md -> фрагменты
  │    (слайд = фрагмент; документ — по заголовкам), два вектора на фрагмент
  ▼                                                          PostgreSQL + pgvector
  поиск и генерация
```

| Шаг | Модуль | Ключевое |
|---|---|---|
| 1 | `bzpo/parsing/detect.py` | pptx и docx — zip с разной структурой; расширение не важно |
| 2 | `bzpo/parsing/convert.py`, `pptx.py`, `docx.py` | единая точка входа `convert(path, vlm=…)` |
| 2 | `heatmap.py`, `charts.py`, `scales.py` | тепловые карты, подписи диаграмм think-cell, шкалы «6 из 8» — кодом |
| 2 | `render.py`, `vlm.py`, `ocr.py` | LibreOffice → картинки; Qwen3-VL: посыл, визуал, текст со скриншотов |
| 2 | `check.py` | полнота ≥ 95%, ноль чисел без опоры в XML — иначе md не сохраняется |
| 3 | `bzpo/registry/draft.py`, `workbook.py`, `loader.py` | черновик, запись, проверки SPEC 4.5, диагностика |
| 4 | `bzpo/ingest/slides.py`, `document.py`, `indexer.py` | нарезка, векторы, версии индекса |

**Слайд не режется.** Слайд — единица смысла и ссылки («слайд 14»); предел
фрагмента презентации — размер её крупнейшего слайда. Документ Word режется по
заголовкам порциями до 500 токенов; таблица и рисунок неделимы.

## 4. Путь запроса: черновик подхода

```
цель + отрасль + ситуация
  │ facet_queries — 6 подзапросов по граням подхода (SPEC 5.1)
  ▼
  │ search по каждой грани: вектор + FTS (8 редких лемм) → RRF → реранкер (50
  │ кандидатов) → boost (отрасль, выигран, свежесть) → MMR
  ▼
  │ assemble_context — фрагменты по кругу граней в бюджет 11 000 токенов;
  │ подпись каждого: проект, заказчик (по публичности), документ, слайд;
  │ широкие таблицы — построчно
  ▼
  │ Qwen3.5 9B + prompts/approach_system.txt, потоковый вывод
  ▼
  │ postprocess — без LLM: числа против фрагментов, несуществующие ссылки,
  │ утверждения без источника и без [вывод], перенос ситуации нового заказчика
  │ в факты прошлых проектов; достоверность по граням
  ▼
  черновик + «Источники» (собирает код) + «Не подтверждено» по граням
```

Модули: `bzpo/search/query.py`, `bzpo/generation/approach.py`, `run.py`,
`validate.py`, `tables.py`, `prompts/`.

**Достоверность грани** = средняя оценка реранкера её фрагментов × доля её
утверждений, прошедших проверки. Эвристика, а не вероятность.

## 5. Кто что делает

| Код (детерминировано) | Модель | Человек |
|---|---|---|
| Текст, таблицы, данные диаграмм из XML | Векторы и реранкинг | Код проекта, публичность, результат тендера |
| Тепловые карты, шкалы, подписи диаграмм | Черновик подхода (Qwen3.5) | Отметка «проверено» в реестре |
| Проверка md против исходника | Черновик строки реестра (GigaChat) | Разбор блока «Не подтверждено» |
| Роли команды по таблице «ФИО / Должность» | Посыл и визуал слайда (Qwen3-VL) | Проверка текста, распознанного с картинок |
| Тип документа по признакам (КП / отчёт) | Текст со скриншотов (Qwen3-VL) | Итоговая правка черновика |
| Поиск, фильтр публичности, «Источники» | | |
| Проверка чисел, ссылок, переноса | | |

**Правило проекта:** что можно определить кодом, определяет код. Обосновано
замерами: на тепловой карте ДЕВ модель верно определила 2 ячейки из 12, код —
96 из 96; модель путала, какой ряд легенды к каким данным относится.

## 7. Данные

```
data/                       не в git: данные заказчиков
  samples/                  только md (и xlsx-таблицы) — то, что индексируется
  sources/                  оригиналы pptx/docx — для проверки и повторной конвертации
  registry.xlsx             реестр: листы «Проекты», «Документы», «Легенда»
  registry_backup_*.xlsx    копии перед заменой реестра
  cache/render, vlm, ocr    рендер слайдов и ответы моделей — повтор без пересчёта
  drafts/                   сохранённые черновики подходов
```

**Реестр.** Лист «Проекты» — колонки прежней таблицы компании плюс «Результат
тендера» и «Статус записи». В индекс попадает только строка со статусом
«проверено». Правила:

- **Публичность:** `open` — заказчика можно называть; `anon` — только
  обезличенное название; `closed` — не использовать. В поиск сейчас допускается
  только `open` (`search.allowed_publicity`), как в SPEC для PoC.
- **Результат тендера:** есть отчёт или акт — `won` автоматически; проект только
  с КП — человек выбирает won / lost / not_submitted.
- **Временный код** `…-DRAFT` к индексации не допускается.

**База.** Схема — `bzpo/migrations/0001_initial.sql`. Идентификаторы
детерминированные (uuid5 от кода проекта, пути файла): повторы не плодят дубли.
Версия индекса считается из модели эмбеддера, её ревизии и параметров нарезки;
новая версия строится рядом со старой и активируется, только если ни один
документ не упал.

## 8. Запуск

```bash
cd ~/project/RAG_v1
./start.sh                                   # Postgres.app + Ollama + страница :8501
```

Консоль (из папки проекта, окружение `.venv`):

```bash
export BZPO_DB__DSN=postgresql://localhost/bzpo HF_HUB_OFFLINE=1
python -m bzpo.parsing convert data/sources/x.pptx --vlm   # файл/папка -> md
python -m bzpo.parsing check x.pptx x.md                  # проверка md против pptx
python -m bzpo.registry draft data/samples/x.md           # черновик строки реестра
python -m bzpo.ingest [--file samples/x.md]               # реестр + индексация
python -m bzpo.search "вопрос" -k 5 [--full]
python -m bzpo.generation approach "цель" --area "отрасль" --situation "..."
python -m pytest tests -q && python -m ruff check .
```

Что важно знать:

- Секреты — только в окружении (`BZPO_DB__DSN`, токены); загрузчик конфигурации
  отвергает их в `config.yaml`.
- На 16 ГБ в памяти одна LLM за раз (`OLLAMA_MAX_LOADED_MODELS=1`, задаёт
  `start.sh`). Страница не даёт запустить две тяжёлые операции одновременно,
  но о процессах из консоли она не знает — не запускайте конвертацию из
  консоли, пока работают со страницей.
- Ответы моделей кэшируются: упавшую конвертацию можно запустить повторно.
- Подмена папки данных для тестов страницы: `BZPO_DATA_DIR`.

## 9. Отличия от SPEC и PLAN

| SPEC / PLAN | Сейчас | Почему |
|---|---|---|
| Эмбеддинги — внешний сервис bge-m3 | Giga-Embeddings 480M в процессе (режим `external` сохранён) | работа на ноутбуке без сервиса; русский; 1024 изм. = схема без миграции |
| Генерация — GigaChat-20B, сервер 24 ГБ | Qwen3.5 9B на запросы, GigaChat Lightning — реестр | 20B не помещается в 16 ГБ; GigaChat Lightning выдумывал факты в разделе заявки |
| Окно 16 384, ответ 3 000 | Окно 24 576, ответ 4 500 | полный формат подхода обрезался; у Qwen3.5 мал KV-кэш |
| Парсинг — Docling, Tesseract/PaddleOCR | Свой разбор XML pptx/docx; Qwen3-VL для картинок и скриншотов | think-cell: подписи — поля `a:fld`, значения — цветом; Docling этого не даёт |
| Чанк 500 токенов с перекрытием | Слайд = фрагмент, не режется; документы — по заголовкам | слайд — единица смысла и ссылки |
| Обогащение чанка — LLM по каждому чанку | Шапка из frontmatter и реестра, без LLM | всё нужное уже в разметке |
| Реестр заполняется вручную | Черновик от GigaChat + проверка на странице | ускорение внесения проектов |
| Тип задачи и 3 сценария | Реализован сценарий Б (описание подхода) | остальное — этапы 3.5–4 |
| Langfuse, трассы | Нет | отложено до сервера |
| Бюджет запроса 60 с | ~2,5–3 мин на ноутбуке | скорость Qwen3.5 на M5 (~23 ток/с) |

Чего в SPEC нет, но сделано: тепловые карты и шкалы по XML, подписи диаграмм
по цвету легенды, распознавание скриншотов в Word, проверка md против
исходника, достоверность по граням, проверка переноса ситуации, форма проверки
реестра, блокировка операций.

## 10. Не реализовано из SPEC

- Эталонный набор вопросов и прогон метрик качества (этап 3) — `bzpo/eval` пуст.
- Разбор запроса: классификация типа задачи, HyDE (этап 3.5). Флаги `use_hyde`
  в `config.yaml` пока ничего не включают.
- Порог «не найдено» (`search.rerank_threshold`) не откалиброван — система
  всегда что-то возвращает.
- Секционный индекс и разделы-образцы; дедупликация и кластеры; граф связей.
- База подтверждений (акты, письма) и сценарии А и В.
- Индекс HNSW (на ~20 тыс. фрагментов понадобится; сейчас перебор быстрый).
- PDF, сканы; маскировка имени заказчика в anon-проектах.

## 13. Открытые решения

1. **anon-проекты в поиске.** Сейчас скрыты. Варианты: пометить проект `open`
   или маскировать имя заказчика при индексации.
2. **Качество толкования картинок.** Qwen3-VL 8B местами поверхностна; варианты —
   исключить посыл и визуал из поиска, модель мощнее на сервере, внешний API
   (оценка конфиденциальности).
3. **Сервер с GPU 24 ГБ** для командного доступа.
4. **Хронометраж «до»** для оценки эффекта в часах и деньгах.
